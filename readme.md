# Reactor TCP Server

这是一个基于 Linux `epoll` 的 C++17 Reactor 模型 TCP 服务器，参考了 muduo 的主从事件循环设计。当前版本已完成一轮稳定性与生命周期修复，服务端可以在多连接场景下稳定运行，并支持优雅退出与线程安全的跨线程任务投递。

## 1. 项目定位

这个项目适合用于：

- 学习 Linux TCP 编程
- 理解 Reactor / one-loop-per-thread 架构
- 理解 `epoll` + 非阻塞 I/O + 事件回调模型
- 演示长度前缀协议与连接管理
- 做 C++ 网络编程的实验与调优基础

当前版本不提供完整的业务协议栈，而是聚焦于底层网络框架的稳定性和可扩展性。

## 2. 当前版本（v16）更新摘要

本次服务器更新重点修复了几个关键问题：

- `EventLoop::RunInLoop` 改为线程感知：在 loop 线程内直接执行，跨线程任务通过 `AddTask` + `eventfd` 唤醒循环
- `HandleTasks` 采用“锁内 swap，锁外执行”的模式，避免任务队列中的递归加锁和自死锁
- 新增 `EventLoop::Quit()`，用于优雅退出事件循环，`~EventLoop()` 中自动触发退出
- `TcpServer::~TcpServer()` 先关闭所有子循环，再 join 线程，修复退出时的挂起/异常
- 非法帧长（如 0 或超过 4096）直接断开连接，不再造成流解析错位
- 清理了遗留调试代码与不必要的跨线程任务投递行为

这些改动使项目从“能跑”进入“稳定可用”的状态，适合继续扩展成更完整的网络服务框架。

## 3. 架构说明

核心组件：

- `Acceptor`：监听端口，接受新连接
- `EventLoop`：管理 `epoll` 事件循环和异步任务
- `Channel`：fd 与回调事件的封装
- `Connection`：单个 TCP 连接的读写与消息解析
- `TcpServer`：主从 Reactor 入口，负责 accept + loop 分发
- `Buffer`：网络字节缓冲区，处理半包/粘包问题
- `Client`：命令行客户端，发送文本消息给服务端

服务端采用：

- 主线程负责 accept 新连接
- 多个子线程各自运行一个 `EventLoop`
- 新连接轮询分配给不同子 loop 处理

这是一种典型的 one loop per thread 结构。

- GNU Make

## 5. 编译与运行

### 编译

```bash
make
```

编译成功后，会生成：

- `Server`
- `Client`

### 清理

```bash
make clean
```

### 运行服务端

```bash
./Server
```

默认配置：

- IP：`127.0.0.1`
- 端口：`9999`
- 子事件循环数：`4`

### 运行客户端

在另一个终端执行：

```bash
./Client
```

连接成功后即可输入文本消息并按回车发送。

## 6. 通信协议

项目采用长度前缀协议（length-prefixed protocol），每条消息结构为：

| 字段 | 长度 | 说明 |
| --- | --- | --- |
| 消息长度 | 4 字节 | 网络字节序的无符号整数 |
| 消息正文 | 变长 | 实际发送内容 |

规则：

- 头部只记录正文长度，不含长度字段自身
- 通过 `htonl` / `ntohl` 做字节序转换
- 当消息体长度为 0 或超过上限（当前设为 4096）时，会被视为非法帧并断开连接

这样可以避免 TCP 字节流的边界模糊问题。

## 7. 当前功能行为

当前服务端的行为是：

- 接收客户端连接
- 读取长度前缀消息
- 解析并输出消息内容
- 打印时间戳、客户端 fd 和消息内容
- 在客户端断开时清理连接

当前版本不做：

- 回显消息
- 群发广播
- 业务分发路由
- 复杂的会话管理

它更偏向一个高质量的底层网络框架 demo，而非完整的即时通讯或 WebServer。

## 9. 版本特性概览

从工程迭代角度看，该项目已经完成以下关键阶段：

- 初始版本：简单 Reactor，存在连接生命周期和边界处理问题
- 中期版本：完善 Buffer、`epoll` 事件处理、半包/粘包处理
