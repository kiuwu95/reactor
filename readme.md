# Reactor TCP 服务器

这是一个使用 C++17 编写的 Linux TCP Reactor 示例项目，整体设计参考 muduo。服务端基于 `epoll` 处理连接，并将新连接轮询分配给多个子事件循环；项目同时提供一个命令行 TCP 客户端。

## 功能

- 使用非阻塞监听套接字和 `epoll` 处理连接事件。
- 主事件循环负责接收连接，多个子事件循环负责处理已连接客户端。
- 通过长度前缀协议处理 TCP 消息，避免依赖 TCP 的报文边界。
- 服务端为收到的消息打印时间戳、客户端文件描述符和消息内容。
- 提供可交互的命令行客户端，用于向服务端发送文本。

> 当前服务端只接收并打印消息，不会向客户端回显或广播消息。

## 环境依赖

- Linux（使用 `epoll`、`accept`、`recv` 等 POSIX 接口）
- 支持 C++17 的 g++
- pthread
- gperftools 的 tcmalloc（链接库 `libtcmalloc`）
- GNU Make

## 编译

在项目根目录执行：

```bash
make
```

成功后会生成 `Server` 和 `Client` 两个可执行文件。清理生成文件：

```bash
make clean
```

## 运行

先在一个终端启动服务端：

```bash
./Server
```

服务端默认监听 `127.0.0.1:9999`，并创建 4 个子事件循环。

再在另一个终端启动客户端：

```bash
./Client
```

连接成功后，在客户端输入一行文本并按回车，服务端会打印收到的内容。可以启动多个客户端观察连接分配与消息日志。客户端和服务端的默认地址、端口在各自构造/连接接口中设置（`TcpServer` 和 `Client` 的默认参数）。

## 消息协议

每条消息由以下两部分组成：

| 字段 | 长度 | 说明 |
| --- | --- | --- |
| 消息长度 | 4 字节 | 无符号整数，网络字节序（大端） |
| 消息正文 | 按长度指定 | 原始字节序列 |

长度字段仅表示正文长度，不包含长度字段本身。客户端和服务端都使用该格式进行收发。

## 项目结构

```text
.
├── include/              # 服务端、客户端及缓冲区等头文件
├── Acceptor.cpp          # 监听套接字与新连接接收
├── Channel.cpp           # fd 与 epoll 事件及回调的封装
├── EventLoop.cpp         # epoll 事件循环和连接管理
├── Connection.cpp        # 服务端连接与消息接收
├── TcpServer.cpp         # 服务端及主/子事件循环
├── ServerBuffer.cpp      # 服务端读写缓冲区
├── Client.cpp            # 客户端连接与收发
├── ClientBuffer.cpp      # 客户端读写缓冲区
├── Svr.cpp               # 服务端入口
├── Clt.cpp               # 客户端入口
└── Makefile
```
